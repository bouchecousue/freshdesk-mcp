# Security reports / Signalements de sécurité

## English

Use GitHub's **Report a vulnerability** button in this repository's Security tab for a private report. Include affected versions, a synthetic reproduction, expected behavior and impact. Do not include real API keys, OAuth tokens, database files or customer data. Do not file sensitive details as a public issue.

If private reporting is unavailable, open a public issue asking for a private reporting channel, without exploit details or sensitive data. No response-time commitment or independent security certification is implied. Operators should evaluate the current default branch and review [security and operations](docs/en/security.md) before deployment.

## Français

Utiliser **Report a vulnerability** dans l'onglet Security du dépôt pour un signalement privé. Indiquer les versions concernées, une reproduction synthétique, le comportement attendu et l'impact. Ne pas joindre de vraie clé API, jeton OAuth, base ou donnée client. Ne pas publier les détails sensibles dans une issue.

Si le signalement privé n'est pas disponible, ouvrir une issue demandant un canal privé, sans détail d'exploitation ni donnée sensible. Aucun délai de réponse ni certification de sécurité indépendante n'est annoncé. Examiner la branche par défaut actuelle et le guide [sécurité et exploitation](docs/fr/security.md) avant déploiement.
